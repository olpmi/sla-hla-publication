The corrections below were applied to the repository's own tables and data
dictionary. They are metadata and presentation changes; **no published
measurement changes value.** Apply them to the submission files if the
supplementary tables are revised.

## 1. Table S4b — separate historical fields from current values

**Why.** Six columns of Table S4b describe the *submitted* version of the
manuscript, not the final one. Read beside the current measurements they invite a
specific misreading — that Figure 5F prints 3.4 Å for HLA-C\*07:01. It does not:
the final legend and artwork name HLA-C\*07:02 and the panel prints 2.6 Å, which
is `round(rmsd_cealign_CA, 1)` of the recomputed 2.638 Å. All nine displayed
panels agree with their adopted measurement; see
`outputs/reports/structural_panel_audit.csv`.

**Move these six columns out of Table S4b** into a new sheet,
`S4b_provenance` (`TableS4b_provenance_submitted_version.csv`), renaming each so
it names the version it describes:

| old column (Table S4b) | new column (Table S4b provenance) |
|---|---|
| `hla_allele_in_legend` | `hla_allele_in_submitted_legend` |
| `allele_match` | `allele_match_vs_submitted_legend` |
| `rmsd_reported_in_manuscript` | `rmsd_printed_in_submitted_figure` |
| `delta_cealign_minus_reported` | `delta_cealign_minus_submitted` |
| `delta_super_minus_reported` | `delta_super_minus_submitted` |
| `delta_align_minus_reported` | `delta_align_minus_submitted` |

The provenance sheet also carries `panel_name`, `final_figure`, `panel`,
`record_level`, `hla_allele_in_model` and a `note` column.

**Add these four columns to Table S4b:**

| column | value |
|---|---|
| `record_level` | `displayed panel` for the nine published panels; `historical comparison (not a displayed panel)` for `class1_F_alt` |
| `rmsd_displayed_in_final_figure` | `round(rmsd_cealign_CA, 1)`; blank for `class1_F_alt` |
| `displayed_equals_round1_of_cealign` | check that the printed value equals the measurement rounded to one decimal — true for all nine panels |
| `identity_method` | how the two identity columns were produced (MAFFT, or "not recomputed") |

`record_level` previously read `model pair` on every row, which did not
distinguish the published panels from the historical comparison.

## 2. Data dictionary

- Move the six renamed entries above from the `S4b` block to a new
  `S4b_provenance` block, and mark each description **HISTORICAL**, stating that
  the final figure prints `round(rmsd_cealign_CA, 1)`.
- Correct `hla_allele_in_legend`'s description: it read "HLA allele named in the
  published legend", which is now wrong — the final legend names
  `hla_allele_in_model`. It becomes "HLA allele named in the SUBMITTED
  manuscript legend".
- Add dictionary entries for the four new `S4b` columns.
- Correct the two identity descriptions to name their method and denominator:
  `percent_identity_over_shared_positions` is MAFFT identity between the two
  modelled sequences over positions where both chains have a residue;
  `n_positions_both_present` is that count.

The corrected dictionary is regenerated by `make reproduce` at
`outputs/tables/publication/PUBLICATION_TABLES_DATA_DICTIONARY.csv`.

## 4. Not a change — Table S1

Five `local_name` differences reported in the previous release were a defect in
*this repository's* parser, not in the approved table, and have been fixed here.
The approved Table S1 needs no change on that account.

Four cells still differ, all on accessory-locus alleles (SLA-DQA\*01:01,
SLA-DQA\*02:02:02, SLA-DRA\*02:03:01) that appear in more than one curated
haplotype. The approved table reports one haplotype; the rule it used to choose
is not recorded. No manuscript result depends on these cells. See
`outputs/reports/tableS1_cell_differences.csv`.
