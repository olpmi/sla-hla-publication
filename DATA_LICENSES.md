# Data licences and redistribution

`LICENSE` (MIT) covers **the code in this repository**. It does not cover
third-party data or model weights. Each resource is assessed on its own terms
below. Where the basis for redistribution is unresolved, this file says so rather
than implying permission.

## IPD-IMGT/HLA and IPD-MHC

**The terms are not a prohibition.** Per https://www.ebi.ac.uk/ipd/imgt/hla/licence/
the data are under a Creative Commons Attribution-NoDerivs licence, which
**permits redistribution of the unmodified data with credit**. Three conditions
apply:

1. Redistribution of the data *as they are* is allowed, provided the database is
   cited: Barker DJ, Natarajan RHL, Cooper MA, Hopper SJF, Yates AD, Marsh SGE,
   Robinson J. *The IPD-IMGT/HLA Database: recent developments in sequence
   submission.* Nucleic Acids Research (2025) 54:D1152–D1158.
2. Distributing a **modified** version requires prior permission from the
   database. We have not sought it.
3. The database states it is "strongly opposed to the mirroring of the data" and
   asks for links instead.

**What this repository does.** We could lawfully ship the unmodified
`hla_prot.fasta`, `MHC_prot.fasta` and the sixteen alignment files under (1). We
do not, for two reasons, neither of which is that redistribution is forbidden:
condition (3) is an explicit request from the data provider, and pinning a URL
and a SHA-256 honours it while still giving a reader a byte-exact route to the
same files; and the *derived* tables our pipeline builds from those files —
parsed parquet, DIAMOND databases, the projected registry-coordinate alignments —
are modified versions under (2), so shipping them would need permission we have
not requested.

The consequence for reproduction: **none for `make reproduce`**, which starts
from analysis results rather than sequence. It affects only the optional upstream
rerun and Table S1's identity columns.

## CIWD 3.0.0

The 18th International HLA and Immunogenetics Workshop distributes CIWD 3.0.0
publicly, but we have not located an explicit licence granting redistribution,
and absence of a stated prohibition is not a grant. **The basis for redistributing
it is therefore unresolved**, so the files are acquired rather than shipped, with
URL and SHA-256 pinned in `data/MANIFEST.json`. Cite Hurley CK *et al.*, *HLA*
2020;95:516–531.

## HLA Eplet Registry

Research use only; redistribution prohibited. **No registry table, raw or parsed,
is in this repository.** Obtain the export directly from
https://www.epregistry.com.br/ (account required).

The MICS-Lab/pelc eplet tables carry that project's own licence, but their
content is EpRegistry-derived, so they are treated under the same restriction and
are likewise not shipped.

## The eplet position mask — basis unresolved, therefore excluded

### What it is and how it was constructed

A set of mature-protein residue positions — **61 class I, 52 class II** — derived
from the HLA Eplet Registry export by pooling the flattened `resi` column per
locus over the alleles whose name begins with that locus, then intersecting with
the positions the agreement analysis covers. It retains integer positions and
nothing else: no eplet names, no allele assignments, no evidence categories, no
exposition values, no registry row structure.

### The applicable terms

The registry's terms are research use only and prohibit redistribution of its
tables. They do not address derivatives, and **no permission covering this
derivative has been sought or granted**.

**The basis is therefore unresolved, and the mask is excluded.**
`data/source_data/figureS8_S13_UPDATED_plotted_values.csv` and
`figureS_identity_eplet_agreement_corrected_p_plotted_values.csv` ship without
their `is_eplet_associated` columns, and `eplet_position_mask_comparison.csv`,
which enumerated positions, is not shipped at all.

### Generating it locally

With an appropriately obtained registry export:

```bash
python -m slahla_pub.eplet_mask --from-registry /path/to/export   # writes data/local/eplet_positions.csv
python -m slahla_pub.eplet_mask --check                          # confirms it was picked up
```

**Required release:** the export as accessed **2026-08-05** from
https://www.epregistry.com.br/ (an account is required). A later release gives a
different mask and therefore different statistics — the published numbers are
pinned to that access date.

**Required format:** the registry's **per-allele export**, one CSV per database,
with these columns:

```
Name,Evidence,Exposition,Allele,resi,resn
1C,,High,C*01:02,[[1]],[['C']]
2D,B,Intermediate,DQA1*01:01,[[2]],[['D']]
```

`Name` is the *eplet* name (`62GE`, `1C`, `144KR+151H`) and carries no locus;
`Allele` is where the locus comes from. The importer reads the locus from
`Allele` only and refuses a file without that column rather than guessing — a
file of `eplet,resi` alone cannot say which locus a position belongs to. File
names are used only to report what was read, never to assign a locus, so
`ABC.csv` and `DRB_DQ_DP.csv` work as well as any other names. Two files suffice:
the ABC export and the DR/DQ/DP export.

**The selection rule, unchanged from the published analysis:**

1. Keep eplets with `Evidence` in {A1, A2, B} **or** `Exposition == 'High'` — the
   disjunction the original analysis applies, not a conjunction.
2. Keep rows whose `Allele` is at one of the class's loci: **A, B, C** for class I,
   **DRB1, DRB3, DRB4, DRB5, DQB1** for class II. DP and the alpha chains are
   excluded — the SLA cohort has no comparator there, and including DP would add
   five positions that the published mask does not contain.
3. Flatten the nested `resi` column to integer positions; take the union per class.
4. Intersect with the positions the agreement matrix covers, so the mask cannot
   name a position the analysis never scores.

The importer rejects an empty directory, a table missing any required column, a
table with no rows, an export with no allele at a class's loci, and an export
where nothing passes the filter — each with a message naming the problem. It
never writes a partial or empty mask.

Run against the pinned export it reproduces the published mask **exactly**: the
same 61 class I and 52 class II positions, by membership and not merely by count.
`validation/eplet_mask_membership.json` records those rules and the membership
fingerprints.

`data/local/` is git-ignored: nothing written there is redistributed by this
repository.

`outputs/reports/missing_inputs.json`.

### One resource, assessed once — and an open question

This assessment covers the registry as a resource, so it applies to every
derivative of it and not only to the mask. **The eplet-name columns of the
approved Tables S5 and S6 carry registry content directly** — `eplet_names`,
`eplet_loci_defining`, `eplet_name_source`, `eplet_named_in_registry_group_mask`
— and they rest on the same unresolved basis. They are retained here because
those are the manuscript's own published supplementary tables, carried as the
approved comparison baseline rather than redistributed as registry data by this
repository. **This is flagged as unresolved and awaiting the authors' decision**;
`slahla_pub.eplet_mask` already provides the mechanism if those columns are to be
withheld too.
